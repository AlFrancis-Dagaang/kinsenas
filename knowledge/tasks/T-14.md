# T-14: Installments, outside transfers and notes

## Acceptance criteria
- [x] Installments: a new Installments page lists fixed-term purchases, each with a name, total, number of months, monthly amount, due day and paying account. Pay logs an expense from that account linked to the installment, with no category, like a bill payment. The row shows "3 of 12 paid" with the pixel bar and the next due date, and is marked finished after the last payment
- [x] Outside transfers: a transfer's "To" accepts one of your accounts or a free-text name. A transfer to a name takes the amount from the paying account, so net worth drops, shows in Activity as "Account → name", and does not count in Income this month, Expenses this month or Budget. Transfers between your own accounts work as before
- [x] Notes: an optional note (up to 200 characters) on entries, debts, goals, installments and recurring bills, set in each create/edit form and shown as a muted line in the lists. Setup is unchanged
- [x] Existing rows keep working with no balance, budget or entry changes; the migration is additive only; unit tests cover installment progress and the outside-transfer balance effect, and a transfer to a name can't make a balance negative
- [x] The account history page (Accounts, per account) shows an entry's note as a muted line under its details

## Findings
- **Outside transfers mostly fall out of the existing math.** `balanceOf` subtracts any non-income entry from `accountId`, and only adds a transfer when `toAccountId` matches, so a transfer with `toAccountId = null` already lowers the payer and credits nobody. `monthTotals` only sums `income` and `expense`, and `budgetFor` only counts `expense`, so Income/Expenses/Budget already ignore transfers. `deleteEntry` credits `toAccountId` only, so deleting an outside transfer needs no new rule (money returns to the payer). What blocks it today: the DB check `transactions_transfer` (a transfer must have a different `to_account_id`), the Zod rule in `saveEntry`, the entry form's To select, and four places that print `toAccount` and would show `null` (Activity page, Overview recent, account history, and the goal page, which only lists goal transfers and is unaffected).
- **Transfers can't be edited**, only added and deleted, so notes on entries are set when adding.
- **Installments mirror bills but simpler**: a bill's cycle logic (partial pay, `cycleStart`) isn't needed. One payment = one month. `nextDueDate(date, "monthly", dueDay)` already clamps to month length and is reused. `progressBlocks(paid, total)` is generic and is reused with month counts. Paid count = `paid_before` + count of linked expenses, like debts' `paid_before`.
- **No negative balances** (project rule): Pay checks the paying account's balance under the same account lock as `payBill`.
- **Account delete**: `installments.account_id` restricts like goals', so `deleteAccount` gets a matching "Move or delete its installments first." check.
- **Notes** are one nullable `note text` column on `transactions`, `bills`, `debts`, `goals` and the new `installments`; Zod (trim, max 200, blank to null) at each action, same as `payee`. Setup inserts without it, so it stays null: setup unchanged.
- **Deploy**: Vercel runs the migration in the build, and old code runs against the new schema for a moment. Every change is additive: new nullable columns, a new table, and the `transactions_transfer` check is replaced by a looser one that still accepts every row old code writes. Old code reading an outside transfer treats it as money out (correct), so no break.
- RLS: new table needs `enableRLS` plus the `ownRows` policy (`app_user` default privileges already cover new tables), and one more case in `lib/rls.test.ts`.
- No `prototypes/`. Code graph not needed.
- Belongs to another task, not planned here: audit log (T-15; it should snapshot notes). Unpaying an installment when its Activity row is deleted (the same follow-up that exists for bills and debts in the retro).

## Worked example (dev holds test accounts only: Payroll 1,000.00, Test bank 150.00, net worth 1,150.00)
Outside transfer: Payroll → "Mom", 300.00.
- Payroll 700.00, Test bank 150.00. **Net worth 850.00** (was 1,150.00).
- Income this month, Expenses this month, Budget left: unchanged. Activity row: "Payroll → Mom", amount 300.00.
- Delete that row: Payroll back to 1,000.00, net worth 1,150.00.
- Try 1,200.00 to "Mom": refused, "Only 1,000.00 in Payroll".
Installment: "Phone", 500.00 × 6 months, due day 15, paid from Payroll, 1 month paid before tracking. Row: "1 of 6 paid", 2 blocks.
- Pay once: Payroll 500.00, net worth 650.00, **Expenses this month +500.00**, Budget unchanged (no category). Row: "2 of 6 paid", next due rolls a month (the 15th, clamped to the month's length).
- Pay it five more times in total until 6 of 6: row shows "Finished", no next due, Pay is gone. Paying with less than 500.00 in Payroll is refused.
